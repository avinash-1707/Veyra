**Existing Next proxy paths**
- `GET /api/search/suggestions` → server call to API `GET /v1/search/suggestions`; it deliberately changes the envelope to `{ suggestions }` and maps failures to 503.
- `GET|POST /api/auth/:path*` → API `GET|POST /api/auth/:path*`, forwards headers/body and preserves upstream response headers/status.
- There is no generic `/api/v1/*` proxy, rewrite, or catalog proxy. Server Components call `VEYRA_API_ORIGIN` directly.

**CORS and environment**
- API CORS is effectively **not emitted**: `corsHeaders()` would allow only configured `VEYRA_APP_ORIGIN` and `VEYRA_API_ORIGIN`, with credentials and `Vary: Origin`, but has no caller. No OPTIONS handler exists.
- This currently works because browser suggestion/auth requests are same-origin Next routes; catalog page calls are server-to-server.
- Unsafe `/v1` mutations enforce allowed `Origin` plus matching `veyra_csrf` cookie/header, except delivery estimation and `/api/auth/*`.
- API production config requires both origins. Web reads `VEYRA_API_ORIGIN` directly with a localhost fallback; no committed `.env` or `.env.example` was found.

**Minimal migration plan**
1. Add TanStack Query and one client-only provider; do not expose `VEYRA_API_ORIGIN` to browser code.
2. Split types and fetchers into domain modules: discovery, intelligence, cart, orders, returns. Use a shared same-origin envelope parser and query-key factories; retire client imports of `catalog.ts`.
3. First migrate only `NavbarSearch` to a discovery suggestion hook, retaining its existing `/api/search/suggestions` response shape, debounce, abort/stale-response behavior, and 503 fallback.
4. Add a read-only Next BFF namespace for public discovery/intelligence reads before migrating page UI into client islands. Preserve API status/error envelopes; do not add mutation endpoints merely for Query.
5. Keep server-prefetch/hydration for migrated page islands so current force-dynamic rendering and unavailable-state behavior remain intact.
6. Defer cart, checkout, orders, and returns hooks until their request-identity contract is explicitly settled. A cookie-forwarding BFF would change current behavior: cart reads presently omit cookies (guest-cart path), while orders forward cookies and returns currently do not. Do not silently “fix” those semantics during a Query migration.
7. Keep auth behind the existing `/api/auth/:path*` proxy and retain same-origin BFF routing rather than relying on currently inactive CORS helpers.
