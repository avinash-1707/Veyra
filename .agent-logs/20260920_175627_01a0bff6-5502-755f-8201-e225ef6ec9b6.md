Current identity is client-derived, not authenticated:

- API default shopper: `local-shopper`.
- API default cart: `local-guest-cart`.
- Any caller can send another shopper’s `x-veyra-shopper-id` and access that shopper’s orders, returns, reviews, and support proposals.
- Any caller can send another `x-veyra-cart-id` and read or mutate that cart.
- A shopper can submit another cart ID in `POST /v1/checkout/quote`; the quote is assigned to the caller-provided shopper ID, but its contents come from that unowned cart.

Existing ownership enforcement is otherwise in the right service/repository paths:
- Orders: `getOrder`, `listOrders`, quote retrieval, and mutation flows scope on `shopperId`.
- Returns/reviews/support: scope via `getOrder(shopperId, ...)`, return/proposal lookup, and shopper-keyed idempotency.
- Persistent SQL queries filter orders/quotes/returns on `shopper_id`.
These are safe only after the route’s shopper ID is a verified session user ID.
