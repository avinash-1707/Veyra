## Recommended smallest production-quality setup

1. **Add one client provider under `app/layout.tsx`**
   - `app/providers.tsx` should be a Client Component.
   - Wrap the app with `QueryClientProvider`.
   - Do **not** make the whole layout a Client Component.

2. **Create the QueryClient via a shared factory**
   - Server: always create a fresh `QueryClient`.
   - Browser: reuse one module-level singleton to survive initial render suspension.
   - Set `staleTime: 60_000` for SSR to avoid immediate client refetch.

```tsx
// app/get-query-client.ts
import {
  QueryClient,
  defaultShouldDehydrateQuery,
  isServer,
} from '@tanstack/react-query'

function makeQueryClient() {
  return new QueryClient({
    defaultOptions: {
      queries: {
        staleTime: 60_000,
      },
      dehydrate: {
        shouldDehydrateQuery: (query) =>
          defaultShouldDehydrateQuery(query) ||
          query.state.status === 'pending',
      },
    },
  })
}

let browserQueryClient: QueryClient | undefined

export function getQueryClient() {
  if (isServer) return makeQueryClient()
  browserQueryClient ??= makeQueryClient()
  return browserQueryClient
}
```

```tsx
// app/providers.tsx
'use client'

import { QueryClientProvider } from '@tanstack/react-query'
import { getQueryClient } from './get-query-client'

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <QueryClientProvider client={getQueryClient()}>
      {children}
    </QueryClientProvider>
  )
}
```

3. **Use SSR hydration only where it pays off**
   - For above-the-fold or SEO-critical data, prefetch in the Server Component and wrap the client subtree in `HydrationBoundary`.
   - For non-critical/interacted-after-load data, plain `useQuery` client fetching is fine.

```tsx
// app/products/page.tsx
import { dehydrate, HydrationBoundary } from '@tanstack/react-query'
import { getQueryClient } from '../get-query-client'
import { ProductsClient } from './products-client'
import { productsQueryOptions } from '@/features/products/queries'

export default async function ProductsPage() {
  const queryClient = getQueryClient()

  await queryClient.prefetchQuery(productsQueryOptions())

  return (
    <HydrationBoundary state={dehydrate(queryClient)}>
      <ProductsClient />
    </HydrationBoundary>
  )
}
```

4. **Fetch handling for separate Hono API**
   - Query functions must throw on non-2xx because `fetch` does not throw by default.
   - Browser requests using cookie auth across origins need `credentials: 'include'`.
   - Server Component prefetches do **not** automatically behave like browser credentialed fetches; if Hono auth depends on cookies, read cookies/headers in Next and explicitly forward the safe auth header/cookie to Hono.
   - For simplest production behavior, prefer same-origin API routing/proxy if possible; otherwise configure Hono CORS with explicit origin + credentials.

5. **Testing**
   - Test hooks/components with a fresh `QueryClientProvider` wrapper per test.
   - Disable retries in tests.
   - With React 18+, use `renderHook` from `@testing-library/react`; no separate hooks testing library needed.

## Evidence

**TanStack’s App Router guidance:** `QueryClientProvider` must be in a Client Component; use a server-new/browser-singleton QueryClient lifecycle; SSR commonly uses positive `staleTime`.  
Evidence: TanStack advanced SSR guide ([source](https://github.com/TanStack/query/blob/feb1efd8/docs/framework/react/guides/advanced-ssr.md#L26-L85)).

**Hydration guidance:** For App Router, prefetch in a Server Component, then render a `HydrationBoundary` with `dehydrate(queryClient)`. TanStack says creating a new QueryClient per Server Component prefetch is the recommended approach.  
Evidence: TanStack advanced SSR guide ([source](https://github.com/TanStack/query/blob/feb1efd8/docs/framework/react/guides/advanced-ssr.md)).

**Fetch query functions:** TanStack requires query functions to resolve data or throw/reject; because `fetch` does not throw on HTTP errors, query functions must check `response.ok`.  
Evidence: TanStack query functions guide ([source](https://github.com/TanStack/query/blob/feb1efd8/docs/framework/react/guides/query-functions.md#L31-L69)).

**Cookie/credential boundary:** Next cookies can be read in Server Components, but cookie writes are only supported in Server Functions or Route Handlers; cookie state is ultimately browser-side.  
Evidence: Next cookies docs ([source](https://github.com/vercel/next.js/blob/canary/docs/01-app/03-api-reference/04-functions/cookies.mdx)).

**Testing:** TanStack recommends a QueryClientProvider wrapper for tests, isolation per test or clearing, and disabling retries to avoid timeout-prone error tests.  
Evidence: TanStack testing guide ([source](https://github.com/TanStack/query/blob/feb1efd8/docs/framework/react/guides/testing.md#L18-L66)).
