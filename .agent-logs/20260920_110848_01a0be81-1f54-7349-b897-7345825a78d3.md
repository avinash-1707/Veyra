## Smallest complete U1 plan

### 1. Resolve U1 inputs before implementation
Create the D-04 discovery fixtures first, covering:
- US/USD display and explicit simulation disclosure.
- Standard shipping threshold/rate and expedited price.
- Address absent, supported address, unsupported/unserviceable address, and expedited-unavailable cases.
- Available, zero-stock, inactive/withdrawn offer, and selected-offer-change cases.

Two contracts are still unspecified and must be decided rather than invented:
1. The public destination input: full address, postal code, or a saved-address reference. U1 browsing is public, so it cannot require the U3 address-book model.
2. The deterministic default selected variant/offer rule when route parameters are absent or invalid (for example, lowest qualifying active offer). This affects displayed price, availability, and delivery.

### 2. Add the catalog/discovery persistence model
Extend the existing catalog schema rather than treating `catalogSeedProducts` as production data:

- Update `packages/db/src/schema/products.ts` for canonical product-only fields; preserve the U0 seed endpoint contract until its replacement is deployed.
- Add `packages/db/src/schema/catalog.ts` for:
  - categories and product/category assignment,
  - product variants and normalized product attributes/specifications,
  - product media metadata,
  - consumer-visible seller profiles,
  - offers (variant, seller, USD minor-unit price, condition, active state),
  - warehouse/offer stock with derived availability inputs.
- Add `packages/db/src/schema/discovery.ts` for privacy-classified `search_events`.
- Export them from `packages/db/src/schema.ts`.
- Add one forward-only migration under `infra/migrations/` with foreign keys, non-negative inventory/money checks, active/public-read indexes, slug/SKU uniqueness, and search/filter indexes appropriate to the approved lexical implementation.

The existing product-level `amount_minor` and `available_quantity` cannot remain the authoritative source once offers and variants exist. The migration must either clearly retain them only for backwards-compatible seed reads or remove them only alongside an explicit API-contract migration.

### 3. Define shared U1 API contracts
Add `packages/contracts/src/discovery.ts` and expand `packages/contracts/src/product.ts` with versioned schemas/types for:

- `GET /v1/categories` and category browse results.
- `GET /v1/search`: query, supported filters, sort, cursor/limit, applied filters, result facts, and pagination.
- `GET /v1/search/suggestions`: typed-query suggestions and related searches.
- `GET /v1/products/:slug`: product facts, media, variants, offers, selected offer/variant, authoritative availability, and delivery state.
- Delivery context/result: address absent versus a simulated promise, with disclosure text and no real-carrier claim.
- Search analytics event payload, using a pseudonymous identifier and the existing 180-day behavior-retention policy.

Keep empty search/category results as successful list responses, not errors. Extend `packages/contracts/src/api.ts` and `apps/api/src/http.ts` only if U1 needs a distinct retryable/degraded error (for example a 503 `service_unavailable`); existing envelopes must remain compatible.

### 4. Implement deterministic API/domain paths
Add a bounded discovery module under `apps/api/src/` (for example `discovery.ts` plus a catalog repository) that:
- Reads catalog data from PostgreSQL, not `catalogSeedProducts`.
- Performs lexical matching and all approved filters before sort/pagination.
- Re-fetches current offer/stock data for result and detail responses.
- Validates requested variant/offer belongs to the product and is selectable.
- Calculates delivery only through a deterministic simulation adapter backed by D-04 fixtures.
- Records redacted/pseudonymous search events without making analytics failure block browsing.

Register public-read routes in `apps/api/src/index.ts`. Existing route policy already classifies `GET /v1/search` and product routes as `publicRead`; do not add AI intent handling in U1.

The static `/v1/products/seed` endpoint should either remain as a U0 compatibility fixture or be explicitly retired in a separately versioned change—not silently repurposed.

### 5. Build the required shopper surface
U1’s definition of done requires an actual shopper journey, so create the missing `apps/web` Next.js application only after its dependency/version and runtime setup are selected. It needs:
- `/`, `/c/[category]`, `/search`, and `/p/[slug]`.
- URL round-tripping for query/filter/sort and selected offer/variant.
- Home/category browse, lexical search/suggestions, result list, and product detail.
- Loading, empty, error, image-failure, unavailable-offer, address-absent, and simulation-disclosure states.
- Keyboard-accessible filters and variant/offer controls.

AI-unavailable in U1 should mean conventional discovery never calls or waits for AI. Do not build an OpenRouter fallback UI or provider call before U5/D-11.
