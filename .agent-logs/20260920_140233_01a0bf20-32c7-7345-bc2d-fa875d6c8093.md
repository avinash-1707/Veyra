Refactor the backend into a clean, modular, maintainable architecture. Preserve all existing API behavior unless a change is explicitly required.

## Required Module Structure

Organize every backend domain module with:

- `route.ts`
  - Defines HTTP routes and handlers.
  - Handles request parsing, validation, authentication/context extraction, and HTTP response mapping.
  - Must not contain SQL queries or business rules.

- `service.ts`
  - Contains domain business logic, orchestration, transactional workflows, and domain errors.
  - Calls repositories.
  - Must not access SQL/database clients directly.
  - Must not depend on HTTP request/response objects or HTTP status codes.

- `repository.ts`
  - Contains all persistence and database-query logic for that domain.
  - Must not contain HTTP concerns, request/response objects, status codes, or business workflow orchestration.

Create one global route registry, such as `src/routes.ts`, that imports and mounts all module routes in one clear place. Do not mount module routes ad hoc across the application.

DRY Principles

- Keep domain-specific logic within its module even if another module has superficially similar code.
- Prefer explicit code over indirection when abstraction would make behavior harder to trace, test, or modify.
- DRY does not mean eliminating every repeated line. Separate domain rules may remain separate.
